# Design and inspect an interface

Identify the primary action or question on the screen. Use the project's components, type scale and spacing conventions. Give the primary action visual priority and keep labels near the controls they describe.

For the actual interaction, design the states a user can reach. A search view might need an initial state, results, an empty result, a loading state and a retry after failure. Keep keyboard focus visible when content changes. Pair status colors with readable text or another cue.

Exercise the flow using representative content, a long label and a narrow viewport. Check keyboard order and what happens when text wraps or the user zooms. Inspect the rendered result when a browser is available. Name any state or viewport you could only check in the source.
